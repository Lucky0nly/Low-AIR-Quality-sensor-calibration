COMPARATIVE ANALYSIS OF CLASSICALMACHINE-LEARNING ALGORITHMS FORREAL-TIME FAULT DETECTION IN MULTIROTOR UAVs
Research Project Report
Submitted as part of the Machine Learning Project
Focus: Classical machine learning (SVM, Random Forest and K-Nearest Neighbors)
Datasets: UAV vibration recordings and UAV-FD flight telemetry
Prepared for academic evaluation
Abstract
Multirotor unmanned aerial vehicles (UAVs) rely on motors, propellers and inertial sensors to maintain stable flight. Mechanical damage or propeller imbalance can alter vibration and flight-telemetry patterns, making early fault detection important. This report compares three classical machine-learning algorithms—Support Vector Machine (SVM), Random Forest and K-Nearest Neighbors (KNN)—using two separate datasets. Dataset 1 contains triaxial vibration recordings labelled Healthy, Damaged and Unbalanced. Dataset 2 contains UAV-FD telemetry recordings labelled Healthy and Fault. Evaluation includes accuracy, Macro-F1, fault precision, fault recall, false-alarm rate (FAR), inference latency and throughput. In the supplied Dataset 1 results, Random Forest achieved the highest accuracy (99.62%) and Macro-F1 (99.57%), while KNN had the lowest latency (0.0516 ms/window). In Dataset 2, KNN achieved the highest accuracy (69.59%) and Macro-F1 (69.26%) among the reported models, but its FAR remained high (42.52%). The findings show that performance depends on the dataset and that classification quality, false alarms and computational speed must be assessed together.
Keywords
UAV fault detection; classical machine learning; vibration analysis; flight telemetry; SVM; Random Forest; KNN; real-time classification.
1. Introduction
Multirotor UAVs are used in inspection, agriculture, monitoring and emergency-response applications. Their reliability depends on the condition of propulsion components and the quality of sensor measurements. A damaged or unbalanced propeller may change vibration patterns, while a fault during flight may also appear in inertial measurement unit (IMU) signals. A monitoring system that detects such changes can support maintenance and improve operational awareness.
Classical machine-learning algorithms can classify sensor windows using features computed from raw signals. This approach is suitable for a comparative study because it allows model performance and inference cost to be measured without relying on deep neural networks. This report focuses on SVM, Random Forest and KNN and evaluates them separately on a vibration dataset and a telemetry dataset.
2. Aim and Objectives
Aim: To compare classical machine-learning algorithms for UAV fault detection in terms of classification performance and computational efficiency.
Describe and analyse two UAV datasets with different sensor modalities and label structures.
Evaluate SVM, Random Forest and KNN on each dataset using consistent, problem-specific metrics.
Compare fault-detection performance, false alarms, inference latency and throughput.
Interpret model behaviour using class-wise results, confusion matrices, signal plots and feature importance where available.
Identify limitations and practical next steps for improving generalization and real-time suitability.

4. Classical Machine-Learning Methods
4.1 Support Vector Machine (SVM)
SVM learns a decision boundary that separates feature vectors belonging to different classes. A kernel such as the radial basis function can model nonlinear boundaries. Feature scaling is generally important, and scaling parameters must be fitted on the training set only.
4.2 Random Forest (RF)
Random Forest combines predictions from multiple decision trees. It can model nonlinear relationships and usually does not require the same feature scaling as SVM or KNN. Feature-importance values can help interpret which extracted features influence predictions, although importance is not proof of causality.
4.3 K-Nearest Neighbors (KNN)
KNN predicts a class using the labels of nearby training examples in feature space. Its performance depends on K, the distance metric and feature scaling. Prediction time can grow with the number of stored training examples, so measured latency should include a clearly specified implementation and batch size.
5. Experimental Methodology
5.1 Preprocessing and windowing
Sensor recordings are loaded, required channels are selected, and windows are created according to the dataset-specific configuration. Invalid or missing values should be checked before feature extraction. The same split and preprocessing rules should be applied to all three algorithms within each dataset.
5.2 Feature extraction
The current Dataset 2 pipeline extracts eight statistical features from each of six IMU channels, producing 48 features per window. The listed features are mean, standard deviation, root mean square (RMS), minimum, maximum, peak-to-peak amplitude, skewness and kurtosis. The Dataset 1 experiment uses windowed triaxial vibration measurements; its exact feature list should be reported from the implemented script to ensure reproducibility. Frequency-domain features such as dominant frequency and spectral energy can be tested as a future extension.
5.3 Training and evaluation protocol
Train SVM, Random Forest and KNN separately on each dataset.
Fit feature scaling only on training data and reuse the fitted transform for testing.
Use a recording-level split where possible to reduce leakage between correlated windows.
Keep the test set untouched during feature selection and hyperparameter tuning.
Report confusion matrices and class-wise metrics alongside aggregate scores.
Measure inference latency and throughput using the same timing procedure and hardware for all models.
6. Evaluation Metrics
Table 4. Metrics used in the comparison
Metric
Interpretation
Accuracy
Fraction of all windows classified correctly.
Macro-F1
Average F1 across classes, giving each class equal weight.
Fault precision
Of windows predicted as faulty, the proportion that are actually faulty.
Fault recall
Of actual faulty windows, the proportion detected as faulty.
False-alarm rate (FAR)
Of actual healthy windows, the proportion incorrectly flagged as faulty.
Latency (ms/window)
Average prediction time for one window under the reported timing setup.
Throughput (windows/s)
Number of windows processed per second.
For binary fault detection, the usual definitions are:
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
FAR = FP / (FP + TN)
TP = faulty windows correctly detected; FP = healthy windows incorrectly flagged as faulty; FN = faulty windows missed; TN = healthy windows correctly classified. Dataset 1 has three classes, so the exact procedure used to derive fault precision, fault recall and FAR should be stated. If Damaged and Unbalanced are combined as a single fault category for these metrics, this binary aggregation should be explicitly documented.

8. Qualitative Analysis
8.1 Signal visualization
Plot AccX, AccY and AccZ over time for representative Healthy, Damaged and Unbalanced recordings in Dataset 1. For Dataset 2, plot acceleration and gyroscope signals from healthy and faulty recordings. Use the plots to inspect amplitude changes, variability, transient events and overlap between classes. These patterns should be described only after they are observed in the actual signals.
8.2 Confusion matrices and error inspection
A confusion matrix should be generated for each model and dataset. For Dataset 1, examine confusion among Healthy, Damaged and Unbalanced. For Dataset 2, separately count missed faults (FN) and healthy windows incorrectly flagged as faults (FP). Inspect misclassified windows to determine whether errors cluster around transitions, noisy segments or signals with similar feature values.
8.3 Feature importance and model behaviour
Random Forest feature importance can be reported to show which features contributed most to its decisions. SVM and KNN can be examined using class-wise error patterns and feature-space visualizations if available. No specific feature should be claimed as important until the corresponding analysis has been run.
9. Real-Time Performance
The supplied inference measurements show that KNN has the lowest latency on both datasets. Dataset 1 KNN latency is 0.0516 ms/window, while Dataset 2 KNN latency is 0.0435 ms/window. Random Forest has the highest reported latency in both datasets (0.2131 and 0.2180 ms/window, respectively). The throughput values show the same general ordering as latency. These values are useful for model-level comparison but do not, by themselves, prove real-time deployment readiness.
A complete real-time assessment should document hardware, software versions, whether feature extraction is included, number of timed repetitions, batch size, warm-up procedure and whether the measurement covers one-window or batch inference. End-to-end time also includes sensor acquisition, window buffering, feature calculation and decision logic.
10. Limitations and Threats to Validity
Dataset 1 has only one healthy recording; a window-level random split could leak recording-specific characteristics across train and test sets.
Dataset 2 has only five recordings and two test recordings, so generalization to other flights and fault conditions remains uncertain.
The Dataset 1 task is three-class, while Dataset 2 is binary; direct score comparisons across datasets should be made cautiously.
The supplied Dataset 1 fault precision/recall/FAR require a clearly documented definition because the dataset has three classes.
Dataset 2 has a high FAR for all models, including 42.52% for KNN, so further work is required to reduce false alarms.
Hyperparameter tuning, repeated trials and uncertainty estimates are not documented in the supplied result values.
Latency depends on hardware and measurement procedure; the values do not include all end-to-end system components unless explicitly measured.
11. Proposed Improvements and Research Contributions
The following are proposed next steps, not claims of completed contributions:
Compare statistical features with additional frequency-domain features such as spectral energy and dominant frequency.
Tune SVM kernel and regularization settings, Random Forest tree count/depth, and KNN neighbour count and distance metric using training-only validation.
Use recording-level validation wherever possible and seek additional independent healthy and faulty recordings.
Choose thresholds and model settings that reduce FAR while preserving an acceptable fault recall.
Report class-wise precision, recall and F1, confusion matrices, and confidence intervals or variation across repeated runs.
Standardize latency measurement and include preprocessing and feature extraction for an end-to-end timing result.
12. Conclusion
This report compares SVM, Random Forest and KNN for UAV fault detection using vibration and flight-telemetry datasets. On Dataset 1, Random Forest achieved the best supplied classification results, with 99.62% accuracy, 99.57% Macro-F1, 100.00% fault recall and 1.28% FAR. KNN was fastest on that dataset. On Dataset 2, KNN achieved the highest supplied accuracy (69.59%), Macro-F1 (69.26%) and fault recall (82.50%), and the lowest latency; however, the 42.52% FAR remains a major limitation. The results therefore do not support a single universally best algorithm. More rigorous recording-level validation, improved features, parameter tuning and transparent end-to-end timing are needed before drawing conclusions about deployment on an actual UAV.
